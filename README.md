## ✨ Ключевые возможности

- 🛡️ **Модерация с проверкой прав и иерархии**: Команды доступны пользователям с ролью `1276893457410953227` или правами Администратора (`Administrator`). Бот не позволит применить санкции к участникам с равной или более высокой ролью.
- 📜 **Официальный свод правил**: Публикация 4 эстетичных Embed-блоков с глубокой иерархией (1.1, 1.1.1) в целевой канал `1303968110377701416` командой `/rules post`.
- 🔒 **Авто-создание канала аудита**: Бот автоматически ищет или создает скрытый канал `#lounge-logs`, куда обычные участники не имеют доступа (`@everyone` скрыт), а модераторы видят всю историю наказаний.
- 🎨 **Rich Embed логирование**: Цветовая дифференциация событий (зеленый, красный, оранжевый, синий), информация о модераторе, нарушителе, причине и длительности.
- ⚡ **Anti-Crash система**: Защита от непредвиденных падений через глобальные перехватчики `unhandledRejection` и `uncaughtException`.

## 💻 Справочник слэш-команд

| Команда | Описание | Аргументы | Доступ |
|---|---|---|---|
| `/ban` | Заблокировать участника на сервере | `target` (пользователь), `reason` (причина), `delete_days` (0-7 дней) | Модератор (`1276893457410953227`) / Admin |
| `/kick` | Исключить участника с сервера | `target` (пользователь), `reason` (причина) | Модератор / Admin |
| `/mute` | Выдать тайм-аут (мут) участнику | `target` (пользователь), `duration` (напр. `10m`, `2h`, `1d`), `reason` | Модератор / Admin |
| `/unmute` | Досрочно снять тайм-аут | `target` (пользователь), `reason` (причина) | Модератор / Admin |
| `/warn` | Вынести предупреждение | `target` (пользователь), `reason` (причина) | Модератор / Admin |
| `/clear` | Удалить сообщения в канале | `amount` (1-100), `target` (фильтр по автору) | Модератор / Admin |
| `/role add` | Выдать роль участнику | `target` (пользователь), `role` (роль), `reason` | Модератор / Admin |
| `/role remove` | Снять роль с участника | `target` (пользователь), `role` (роль), `reason` | Модератор / Admin |
| `/rules post` | Опубликовать регламент правил | *нет* | Модератор / Admin |
| `/setup-logs`| Инициализировать канал логов | *нет* | Модератор / Admin |
| `/userinfo` | Карточка пользователя | `target` (необязательно, по умолчанию автор) | Все участники |
| `/serverinfo`| Статистика сервера | *нет* | Все участники |

## 🔑 Настройка в Discord Developer Portal

### Шаг 1. Создание приложения и бота
1. Перейдите на [Discord Developer Portal](https://discord.com/developers/applications).
2. Нажмите кнопку **«New Application»** в правом верхнем углу, введите название (например, `Lounge Bot`) и подтвердите создание.
3. Перейдите во вкладку **«Bot»** в левом меню:
   - Нажмите **«Add Bot»** (если бот еще не создан).
   - Под никнеймом бота нажмите кнопку **«Reset Token»**, подтвердите действие и скопируйте полученный токен. Сохраните его — это ваш `DISCORD_TOKEN`.

### Шаг 2. Включение Privileged Gateway Intents (Обязательно!)
В этой же вкладке **«Bot»** прокрутите страницу вниз до блока **«Privileged Gateway Intents»** и активируйте тумблеры:
- ✅ **Server Members Intent** *(критически важно для работы `/userinfo`, `/serverinfo` и системы модерации)*
- ✅ **Message Content Intent** *(для расширенной работы с сообщениями)*
- Нажмите кнопку **«Save Changes»** внизу.

### Шаг 3. Получение Client ID и Guild ID
1. Во вкладке **«General Information»** скопируйте **APPLICATION ID** — это ваш `CLIENT_ID`.
2. В самом приложении Discord включите режим разработчика: `Настройки пользователя` ➔ `Расширенные` ➔ `Режим разработчика` (включить).
3. Кликните правой кнопкой мыши по иконке вашего Discord сервера и выберите **«Копировать ID сервера»** — это ваш `GUILD_ID`.

### Шаг 4. Приглашение бота на сервер
1. Перейдите во вкладку **«OAuth2»** ➔ **«URL Generator»**.
2. В блоке **SCOPES** отметьте:
   - ✅ `bot`
   - ✅ `applications.commands`
3. В блоке **BOT PERMISSIONS** отметьте:
   - ✅ `Administrator` (или вручную: `Manage Roles`, `Manage Channels`, `Kick Members`, `Ban Members`, `Moderate Members`, `Manage Messages`, `Send Messages`, `Embed Links`, `View Audit Log`).
4. Скопируйте сгенерированную ссылку внизу страницы и откройте ее в браузере, чтобы добавить бота на ваш сервер.
5. **Важно в настройках ролей сервера:** Перейдите в `Настройки сервера` ➔ `Роли` и перетащите роль бота **выше** ролей обычных пользователей и модерируемых ролей, иначе Discord не позволит боту выдавать роли или наказывать участников.

## 🚀 Локальный запуск на Windows

### 1. Настройка окружения
В папке `discord-bot` создайте файл `.env` на основе `.env.example`:
```env
DISCORD_TOKEN=ваш_токен_бота_здесь
CLIENT_ID=ваш_application_id_здесь
GUILD_ID=ваш_id_сервера_здесь
```

### 2. Запуск через интерактивный скрипт
Просто запустите файл `start.bat` двойным кликом:
- Скрипт сам проверит наличие Node.js.
- При первом запуске автоматически выполнит `npm install`.
- Предоставит удобное меню:
  - **1**: Регистрация слэш-команд в Discord API (`npm run deploy`).
  - **2**: Запуск бота (`npm start`).
  - **3**: Регистрация команд + немедленный запуск.

### 3. Ручной запуск через терминал
```bash
# 1. Установка зависимостей
npm install

# 2. Регистрация слэш-команд на вашем сервере
npm run deploy

# 3. Запуск бота
npm start
```

## ☁️ Бесплатный хостинг 24/7

### Вариант 1: Discloud (Бесплатный хостинг ботов)
[Discloud](https://discloud.com/) — специализированная платформа под Discord-ботов с бесплатным тарифом (100MB RAM, чего более чем достаточно для данного бота на discord.js).

1. В репозитории уже подготовлен файл `discloud.config`:
   ```ini
   NAME=LoungeBot
   TYPE=bot
   MAIN=src/index.js
   RAM=100
   AUTORESTART=true
   VERSION=latest
   ```
2. Выделите файлы проекта (`src`, `package.json`, `package-lock.json`, `.env`, `discloud.config`) и упакуйте их в архив `.zip`.
   *(Важно: папку `node_modules` упаковывать **не нужно**, Discloud установит зависимости сам).*
3. Перейдите на [Discloud Web Dashboard](https://discloud.com/dashboard) или добавьте бота Discloud на свой Discord-сервер.
4. Загрузите `.zip` архив и нажмите **Upload/Start**. Бот начнет работать 24/7.

### Вариант 2: Render.com + UptimeRobot (24/7 Полный автомат)
Облачная платформа [Render.com](https://render.com/) в связке с бесплатным мониторингом [UptimeRobot](https://uptimerobot.com/) обеспечивает **автономную работу бота 24/7** без необходимости вручную продлевать сервер каждый месяц.

#### Как это работает:
1. В `src/index.js` встроен нативный легковесный HTTP-сервер, который слушает порт Render (`PORT=10000`).
2. Бесплатный тариф Render переходит в спящий режим («spin down»), если нет входящих HTTP-запросов более 15 минут.
3. Сервис UptimeRobot каждые 5-10 минут отправляет `GET`-запрос (пинг) на ваш адрес Render, предотвращая переход в спящий режим.
4. При каждом пуше изменений в ваш GitHub-репозиторий Render **автоматически пересобирает и обновляет** бота без прерывания работы.

#### 🛠️ Пошаговая инструкция по настройке:

##### Шаг 1. Публикация репозитория на GitHub
1. Создайте новый репозиторий на [GitHub.com](https://github.com/new) (например, `lounge-discord-bot`). Сделайте его **Private** (приватным).
2. В терминале в папке `discord-bot` инициализируйте git и отправьте код:
   ```bash
   git init
   git add .
   git commit -m "feat: initial commit with Render HTTP keep-alive"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/lounge-discord-bot.git
   git push -u origin main
   ```
   *(Файл `.gitignore` уже защищает ваши секретные ключи `.env` от попадания на GitHub!)*

##### Шаг 2. Развертывание Web Service на Render.com
1. Зарегистрируйтесь или войдите на [Render.com](https://render.com/) через ваш GitHub аккаунт.
2. В панели управления нажмите **«New +»** ➔ **«Web Service»**.
3. Выберите ваш подключенный репозиторий `lounge-discord-bot`.
4. Заполните параметры сервиса:
   - **Name**: `lounge-bot` (любое имя).
   - **Region**: `Frankfurt (EU)` (наименьший пинг для Discord в Европе).
   - **Branch**: `main`.
   - **Runtime**: `Node`.
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free` (бесплатный тариф $0/mo).
5. Прокрутите ниже до раздела **«Environment Variables»** (Переменные окружения) и добавьте:
   - `DISCORD_TOKEN` = *ваш токен бота из Discord Portal*
   - `CLIENT_ID` = *ID приложения (Application ID)*
   - `GUILD_ID` = *ID вашего Discord-сервера*
   - `PORT` = `10000` *(Render обычно подставляет автоматически)*
6. Нажмите **«Deploy Web Service»**.
7. Дождитесь успешного деплоя (в логах появится `🌐 HTTP-сервер для Uptime-мониторинга запущен на порту 10000` и `🚀 Lounge Bot успешно запущен!`).
8. В верхней части страницы скопируйте публичный URL вашего сервиса (например, `https://lounge-bot-xxxx.onrender.com`).

##### Шаг 3. Настройка вечного онлайна в UptimeRobot
1. Зарегистрируйтесь на бесплатном сервисе [UptimeRobot.com](https://uptimerobot.com/).
2. В панели управления нажмите **«+ Add New Monitor»**.
3. Настройте монитор:
   - **Monitor Type**: `HTTP(s)`
   - **Friendly Name**: `Lounge Discord Bot Keep-Alive`
   - **URL (or IP)**: вставьте ваш URL с Render (например, `https://lounge-bot-xxxx.onrender.com`)
   - **Monitoring Interval**: каждые `5 minutes` (или `10 minutes`)
4. Нажмите **«Create Monitor»**.
5. 🎉 Готово! Каждые 5-10 минут UptimeRobot будет опрашивать ваш сервер, а Render возвращать JSON-ответ `{ status: "online", bot: "Lounge Bot#0000", uptime: "..." }`. Бот никогда не уснет и продолжит работать 24/7!

## 🔒 Канал аудита и логирование (`lounge-logs`)

При старте бота или выполнении команды `/setup-logs`:
1. Бот производит поиск канала `#lounge-logs`.
2. Если канал не найден, бот автоматически создает его со следующими разрешениями:
   - `@everyone`: **Скрыт** (`ViewChannel: false`).
   - Бот: Полные права на отправку Embed и чтение сообщений.
   - Роль модератора (`1276893457410953227`): **Доступ разрешен** (`ViewChannel: true`, `ReadMessageHistory: true`).
   - Администраторы сервера: имеют доступ по умолчанию.
3. Вся палитра цветов логирования:
   - 🟢 `0x2ECC71` — Выдача роли, досрочный размут (`/unmute`).
   - 🔴 `0xE74C3C` — Блокировка (`/ban`), снятие роли.
   - 🟠 `0xE67E22` — Исключение (`/kick`), тайм-аут (`/mute`), предупреждение (`/warn`).
   - 🔵 `0x3498DB` — Очистка сообщений (`/clear`), публикация правил, служебные уведомления.

## 📜 Регламент правил сервера

При вызове команды `/rules post` бот публикует 4 структурированных блока в официальный канал `1303968110377701416`:

1. **Раздел 1: Концепция и общие положения Лаунжа**
   - `1.1` Статус правил и зона действия
   - `1.1.1` Презумпция добропорядочности и адекватности
   - `1.2` Незнание правил не освобождает от ответственности
   - `1.3` Языковой регламент
   - `1.4` Официальные каналы взаимодействия
2. **Раздел 2: Культура текстового общения**
   - `2.1` Токсичность, прямые оскорбления и провокации
   - `2.1.1` Разжигание ненависти, буллинг и дискриминация
   - `2.2` Спам, флуд, капслок и злоупотребление разметкой
   - `2.3` Реклама, реферальные ссылки и несанкционированный пиар
   - `2.4` Неприемлемый контент, шок-контент и NSFW / 18+
   - `2.5` Деанонимизация, приватность и распространение чужих данных (Доксинг)
3. **Раздел 3: Регламент голосовых каналов**
   - `3.1` Качество звука, помехи и модификаторы голоса
